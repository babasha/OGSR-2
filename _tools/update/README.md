# Выпуск обновлений (встроенный обновлятор)

Движок: `ogsr_engine/xr_3da/xr_update.h` (там же весь дизайн). Коротко:

- При первом открытии главного меню игра в фоне скачивает `manifest-<платформа>.txt` из **последнего** релиза
  публичного репозитория движка `babasha/OGSR-2`. Платформы: `nx`, `android`, `pc`.
- Манифест подписан Ed25519, а у каждого файла есть BLAKE2b-хэш. Неподписанное или битое игра не трогает.
- Новее установленного → окно в меню: «Обновить / Позже» → прогресс → «Перезапустить».
- Загрузка идёт в `_update/staging`. Подмена происходит **при следующем старте**, в `WinMain`, до того как FS
  откроет хоть один архив. Если среди файлов есть сама программа (`@self` на Switch, `.exe/.dll` на ПК),
  игра сразу перезапускается ещё раз.
- Android: данные обновляются так же, а новый APK отдаётся системному установщику. Игрок подтверждает установку,
  в первый раз Android ещё попросит разрешить установку приложений из OGSR.

## Один раз

1. Ключ подписи лежит вне репозитория: `%USERPROFILE%\.ogsr\update_ed25519.pem` (для `make_release.py` — переменная
   `OGSR_UPDATE_KEY` или `--key`). **Сделайте копию в надёжное место.**
   Без него ни одну уже выпущенную сборку больше нельзя будет обновить: публичный ключ вшит в
   `xr_update.cpp` (`kPublicKey`).
2. Канал — релизы `babasha/OGSR-2` (`kDefaultChannel` в `xr_update.cpp`, `DEFAULT_REPO` в `make_release.py`).
   ⚠**Самый новый релиз OGSR-2 обязан содержать все три `manifest-*.txt`.** Релиз без них (например, обычная
   сборка движка из CI) делает проверку у всех игроков немой до следующего релиза с манифестами.
   `make_release.py` переносит манифесты других платформ в каждый свой релиз, а для ручного релиза движка
   их нужно доложить: `gh release download <прошлый тег> --pattern "manifest-*"` и загрузить в новый.
3. Игровые данные (архивы ТЧ и мода) в публичном репозитории движка — риск жалобы правообладателя на весь
   репозиторий. Клиент умеет брать ассет по полному URL (`src` = `https://...` в строке `a`/`f` манифеста),
   поэтому данные можно держать в другом месте, не выпуская новый клиент.

## Каждый выпуск (WSL)

```bash
T=/mnt/d/OGSR-2/_tools/update/make_release.py
# Switch: --root = папка как на SD (рядом с fsgame.ltx), --self = имя NRO в ней
python3 $T build --platform nx --root /mnt/d/switch_stage/ogsr --self ogsr.nro \
    --tag nx-b2 --build 2 --version 0.2.0 --notes-file notes.txt --out /mnt/d/upd_out/nx-b2
# Android: данные + APK (versionCode из AndroidManifest.xml, его надо поднимать)
python3 $T build --platform android --root /mnt/d/android_stage/files --apk /mnt/d/android_stage/ogsr.apk \
    --apk-code 2 --tag and-b2 --build 2 --version 0.2.0 --notes-file notes.txt --out /mnt/d/upd_out/and-b2
# ПК: корень игры (bin_x64 + gamedata + fsgame.ltx)
python3 $T build --platform pc --root "/mnt/d/OGSR Gunslinger Addon" --exclude 'bin_x64_*' ...
python3 $T verify /mnt/d/upd_out/nx-b2/manifest-nx.txt
```

Потом выгрузить всю папку одним релизом (команда печатается в конце):
`gh release create nx-b2 --repo babasha/OGSR-2 --title "..." --notes-file notes.txt "D:\upd_out\nx-b2\*"`

Что делает `build`:
- сравнивает с манифестом последнего релиза; неизменённые файлы ссылаются на ассеты **старых** релизов,
  поэтому **старые релизы не удалять никогда**;
- файлы от 4 МБ кладёт отдельными ассетами, мелочь пакует в `pack-N.bin` (у GitHub лимит 1000 ассетов на релиз);
- копирует в новый релиз текущие манифесты двух других платформ: `releases/latest` должен отвечать за все три;
- `--build` должен расти внутри платформы, `notes` — до 6 строк, их видно в окне.

Исключается всегда: `_update/`, логи, `user.ltx`, сейвы, `_appdata_`, `args*.txt`, `nx_*.txt`, кэши
конвейеров. Остальное — через `--exclude`. Сначала смотрите сводку по папкам, которую печатает `build`.

## Проверка без GitHub

`_update/channel.txt` в корне игры (одна строка: URL папки с `manifest-*.txt`) переключает канал. Плюс
`--base http://<адрес>:8765` при сборке, затем `python3 -m http.server 8765 --directory <папка>`:
манифест в корне папки, ассеты в `<tag>/`.

Консоль: `upd_status`, `upd_check` (проверить заново), `upd_auto 0` (не проверять при старте).
`-noupdate` в командной строке тоже выключает проверку. Журнал: `_update/update.log`.
